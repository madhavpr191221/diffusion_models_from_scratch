## BR-001 — Unconditional samples drift out of the training image range

- **Status:** Open; sampler equation check passed; EMA partially reduces drift but does not resolve image quality.
- **Observed:** The 50-epoch run `20261012-045942-train-seed-42` completes all 1,000 reverse updates, but generated previews are strongly saturated and show little coherent land-cover structure.
- **Reproduction:** Select that run's `best-val.pt`, use seed 42 and eight patches in the React **Generate** view. Raw tensors are saved under `runs/20261012-045942-train-seed-42/generation/`; previews clip values to `[-1,1]`.
- **Evidence:** Across checkpoints 10, 20, 30, 40, 50, and best validation, 62.3%–69.6% of generated scalar values were outside `[-1,1]`; pairwise pixel RMSE was 2.10–2.34. The first 128 validation images had no values outside that range and pairwise RMSE 0.399. In the best-validation sample trajectory, the mean moved from about `-0.003` at initial Gaussian noise to about `+2.05` at the final sample.
- **How it was found:** Same-seed checkpoint generation was compared using saved raw tensors, channel/range/diversity summaries, and a fixed validation reference. A separate timestep-bin check found low validation epsilon MSE, while direct reverse-trajectory inspection showed the large mean drift.
- **Diagnosis:** The failure is in the generated trajectory/model-sampler interaction. The initial noise had approximately zero mean and unit standard deviation, and the implemented posterior update matches the configured schedule on inspection. The focused equation/indexing check passed, but this does not prove the learned reverse trajectory is correct. Current evidence does not establish dataset corruption or one confirmed code-level root cause.
- **Sampler check:** The checkpoint schedule matched the sampler. Supplied-noise posterior calculations matched exactly at indices 0, 499, and 999; the index-0 output was identical with supplied noise and no noise. No coefficient or index bug was found in these checks.
- **Controlled comparison:** `runs/20261012-064627-train-seed-42/` completed 50 epochs / 101,250 updates. Best raw validation MSE was 0.013333; best EMA validation MSE was 0.013079. With eight samples and seed 42, the raw checkpoint had 65.2% outside `[-1,1]`, pairwise pixel RMSE 2.161, and final trajectory mean `+2.082`. EMA had 64.2% outside range, pairwise RMSE 2.028, and final trajectory mean `+1.050`. The fixed first-128 validation reference had no out-of-range values and pairwise RMSE 0.399.
- **Outcome:** EMA partially reduces the positive mean drift and slightly reduces the out-of-range fraction, but both previews remain strongly saturated and lack consistent coherent land-cover structure. The symptom is reproduced and EMA is not a complete fix; keep the report open. The specific underlying model/sampler-distribution cause remains unconfirmed.
- **Matched-timestep diagnosis:** On one generated trajectory, compare the model's implied clean estimate `x0_hat` with estimates from 128 forward-noised validation images at the same zero-based timestep. At index 500, raw generated `x0_hat` had mean `+2.031` and 87.5% of values outside `[-1,1]`; the validation estimate had mean `-0.152` and 0.12% outside. EMA generated `x0_hat` had mean `+1.042` and 54.4% outside; its validation estimate had mean `-0.164` and 0.09% outside. At index 300, the generated outside fractions were 92.9% raw and 42.6% EMA, versus 0.14% and 0.12% on validation. This shows the reverse path is already far from the clean-image range midway through denoising; the EMA path is less extreme but still substantially off.
- **Global-shift sensitivity probe:** Add a constant `+0.5` to every pixel/channel of validation `x_t`, holding the original clean image and noise construction fixed. The corresponding noise target would shift by about `+0.502`, `+0.521`, and `+0.642` at indices 700, 500, and 300. The mean change in the model's predicted noise was only `+0.014`, `+0.008`, and `+0.007` for raw weights, and essentially the same for EMA. This is consistent with the model being insensitive to per-image global intensity shifts; the U-Net applies GroupNorm repeatedly, which removes feature means. The probe supports this as a hypothesis but does not prove GroupNorm is the sole cause.
- **Next experiment:** Add a small denoiser branch that reads the three per-channel spatial means of `x_t` together with the timestep embedding, predicts three channelwise noise offsets, and broadcasts them over the image before adding them to the U-Net prediction. This gives the model an explicit route for global intensity information around GroupNorm. Retrain one fresh 50-epoch run with the same seed, data, optimizer, diffusion schedule, and EMA; change only this architecture path. Compare same-seed samples to this EMA run using the full sampler. Leave the test split untouched.
- **Resolution evidence:** Not resolved. Validation loss alone does not resolve this report.

### Investigation update — 2026-10-12

The checkpoint configuration exactly matches the sampler's 1,000-step linear schedule and posterior variance setting. A supplied-noise calculation matched the implemented update with zero observed error at indices 0, 499, and 999; at index 0, supplying noise or omitting it produced identical output. This rules against a simple coefficient/index mismatch at those points, but does not prove the learned reverse trajectory is correct. The controlled EMA run and matched-seed comparison are now complete; see the outcome above.

The timestep-bin validation check produced epsilon MSEs of 0.05780, 0.01002, 0.00334, 0.00124, 0.00040, and 0.00027 for timestep ranges 0–99, 100–299, 300–499, 500–699, 700–899, and 900–999, respectively. This evaluates predictions on validation images noised directly by the known forward equation. It does not evaluate predictions on states produced by repeatedly feeding the model's own reverse updates back into itself. The rising generated-image mean therefore marks a mismatch between a successful fixed-input loss diagnostic and the actual free-running generation path; it does not, by itself, identify the responsible component.

### Stage 10 follow-up � Original U-Net comparison run (2026-10-12)

The original-architecture experiment is intended to help separate the prior compact-model result from a mismatch between that model and the paper's CIFAR-10 DDPM network. The PyTorch port is configured for EuroSAT's 64�64 RGB patches, unconditional noise prediction, the 1,000-step linear schedule, and fixed-large reverse variance. This is a new controlled architecture/training experiment, not a confirmed fix for BR-001. The GPU pilot completed 50 updates at 0.517 updates/second with 3.52 GB peak memory using microbatch 16 and effective batch 128; the projected 800,000-update runtime is approximately 18 days before overhead. Sample quality remains unknown until the full run produces checkpoints and matched-seed generations. Keep BR-001 open until raw sample and trajectory diagnostics are assessed. Training and validation are the only splits used; test remains untouched.

The full original-U-Net run was started under `runs/20261012-103416-train-seed-42/`. At the latest implementation check it was running, with 20/800,000 updates recorded. It is too early to assess whether the architecture improves BR-001; no generation conclusion is drawn from the pilot or initial loss values.

### Runtime decision � full-scale run stopped (2026-10-12)

The paper-scale 800,000-update run was not feasible at the measured GPU throughput. It stopped at update 125 before saving `latest.pt`; it has no resumable checkpoint and is not being continued. This is a runtime planning correction, not a model or sampler bug, and it provides no generation-quality evidence. The practical replacement is 50 EuroSAT epochs (6,350 updates), with proportionally shorter warmup and EMA settings, periodic resumable state, and validation every five epochs. The new run is `20261012-104411-train-seed-42`. BR-001 remains open pending generated-sample evidence.
